# worldline_qc — Multi-Camera 三期（四世界线）交付组质检

三期一组数据 = 4 条世界线 A/B/C/D、12 路视频、48 个文件（交付说明 v1.1 起每路多一个 multicam_sync_i.json）。本包对**一个采集组**做本地自动质检，
输出机器可读 JSON 与一页自包含 HTML（中文），HTML 里把需方的每条要求和「是否达标」对照列出。
与同目录的 `engine_qc`（二期 docs/69 口径）并列，复用它的 ffprobe/响度、位姿差分、解耦判据与数学工具。

## 用法

```bash
cd engine-data/qc
python -m worldline_qc check-group <采集组目录> --expect-duration-s 120 \
    --html out.html --json out.json [--no-pixels] [--thumbs 6] [--roles roles.json]
```

- 退出码同 `engine_qc`：0 通过 / 1 有 FAIL / 2 有 UNVERIFIED（该跑没跑）。
- 依赖：标准库 + `ffprobe`/`ffmpeg`（视频面）；**像素面**额外要 `numpy` + `opencv-python(-headless)`，
  缺了则像素面全部 UNVERIFIED，判定不会是 PASS（不装等于「没检查」，不是「检查通过」）。
- `--roles`：覆盖角色表，`{"AB/2": "free"}`（遍布局）或 `{"2": "free"}`（平铺）。

支持两种目录布局（`loaders.py`）：

| 布局 | 形态 | 角色来源 |
|---|---|---|
| 需方平铺 | `<组>/{video,systeminfo,action_camera}_{1..12}.*`，1–3=A（固定/自由/自由）、4=B、5–8=C（固定/自由/追背/第一人称）、9–12=D | 交付说明固定表 |
| 内部「遍」 | `<组>/{AB,C,D}/*_{1..4}.*` + `README.md` + `manifest.json`（`stage-group-deliver` 产物） | README 路表 + manifest.worldlines |

`README.md` 和 `manifest.json` 放在组文件夹里，或者像 `stage-group-deliver` 写的那样放在旁边（`<组名>.README.md`、
`<组名>.manifest.json`）都认，里面的优先。Windows 控制台先设 `PYTHONIOENCODING=utf-8`（默认 GBK 会在中文处崩）。

「遍」布局会被 `pack.layout` 判 FAIL（交付说明要求平铺），但其余规则照常跑，方便交付前自检。

## 状态口径

| 状态 | 含义 | 影响判定 |
|---|---|---|
| PASS | 自动核验通过 | — |
| FAIL | 硬性条款不通过 | 组判定 FAIL |
| WARN | 已量化但需方口径未定，或内部演示件已知差距 | 不阻断，报告单列 |
| MANUAL | 只能给证据（缩略图/曲线/统计），须人看画面或试听 | 不阻断，报告单列 |
| SKIP | 本路/本组不适用 | — |
| UNVERIFIED | 该跑没跑（工具链/文件缺失） | 组判定 UNVERIFIED（不得放行） |

组判定 = FAIL > UNVERIFIED > PASS。需求条款的结论取命中规则里最严重的状态；没有自动规则的条款按默认口径列出，不会从总表消失（`requirements.py`）。

## 需求条款摘要（规则的事实源）

**交付单位与文件**：一组 = A(3)+B(1)+C(4)+D(4) = 12 路 × (video_i.mp4 / systeminfo_i.json / action_camera_i.json / multicam_sync_i.json) = 48 文件（v1.1 以前 36），缺任一世界线不算完整交付；每组计时 120 s 只算一次。同一采集组内平铺、编号 1～12（A=1–3：1 固定、2/3 自由运镜；B=4；C=5–8：固定/自由/追背/第一人称；D=9–12 同 C），文件名带下划线，目录 `供应商分区/Multicamera3/gameProcessName/YYYY_MM_DD/YYYY_MM_DD_场景名称_标注序号/`，元信息表随包上传，交付表登记 48 个 TOS 地址、世界线/相机类型/受控人物/控制开始时刻/事件是否改变。每路 120 s / 30 fps / 3600 帧，禁动态帧率与动态分辨率。

**视频与运行参数**：全屏不裁剪不加黑边；宽高均 ≥1080；画幅 16:9 1920×1080 占 60%、9:16 1080×1920 占 20%、4:3 ≥1440×1080 占 10%、3:4 ≥1080×1440 占 10%（批次层面）；像素宽高与 systeminfo 一致。焦距 18/24/35/50 mm 各 25%（批次）；单条内 FOV 固定，禁滚轮变焦。同一世界线内严格帧同步；不要求 12 路同时录制。游戏运行帧率 ≥30，JSON 记实际 fps；动作与视频延迟 ≤20 ms；不得掉帧、不得后处理补帧。

**画面与声音**：严禁噪点/锯齿/抖动/闪屏/黑白屏/花屏/跳剪/马赛克/拖影/异常半透明/闪白/场景突变/边走边加载；不得出现 UI/logo/水印/帧率显示/弹窗/菜单/通知/桌面切出/指针（游戏场景自带广告牌不受限）；自由相机不带手部模型；各相机模型互不可见；不得拼接、切换视角模式、录读档界面；每条世界线从逻辑第 0 秒完整录到 120 s；不得穿模；遮挡只允许单次 1–2 s；**动态主体可见 ≥80% 时长**（所有路，含固定机位与第一人称）；**运动像素 ≥50%**（判定法待确认）；音频清晰连续原声、无 BGM、不得无声，C/D 干预后音频对应改变后事件。采集场地 10 m×10 m 以上平整空地；画面内 6 人（D 为 7 人）。

**相机与运镜**：固定机位 A/C/D 各 1 路，位置不变只允许平滑转向；B 无固定机位。A 的两路自由运镜过半时长内不得同步（同时静止/同向摇/机械跟随）。自由运镜每路随机分 1–10 段，每段至少一种六向平移以外的运镜，参数随机、段间平滑、速度均匀分布，**每路包含六向平移**；固定/追背/第一人称不套用。共视 ≥50%（同一世界线内多路同帧从不同角度看到相同主体；B 不适用；参与相机范围待确认）。运镜类目树批次覆盖。运动参数 p95 上限：平移 6 m/s、转动 90 °/s、加速度 8 m/s²、150 °/s²、jerk 20 m/s³、600 °/s³；视觉上不得急停/甩动/抖动（docs/69 另有瞬时 10 m/s 与 roll ±15°）。三期第三人称跟随 FOV 30–55（水平/垂直未明）。

**世界线**：A 6 人照剧本、无接管无新增、3 路同步，作为对照，基线可确定性重播。B 重读基线，1 路真实输入自由相机（WASD 移动、鼠标视角、Q/E 升降），不控制人物不改变事件，不得先生成轨迹再反推输入。共同基线：每条世界线各自从第 0 秒基线恢复；B↔A、C 接管前↔A 逐帧复现；C 接管后/D 受控人物按真实输入，未受干预部分继续按基线，受干预部分差异须能对应具体控制行为；同一世界线内多路记录同一世界状态；C/D 各有「原事件被改变/未改变」两种情形（50/50 批次）；**JSON 的 time 记录本轮真实系统时间，不回拨不伪写**。C 随机选 6 人之一，第 N 整数秒接管，接管前如实记录基线动作、不伪造接管输入。D 新增第 7 人从第 0 秒真实控制，动画连续无穿模悬浮抽搐。

**真实输入与字段**：记录真实输入及组合键（同帧叠加不求和），键码 W=87 A=65 S=83 D=68 Q=81 E=69；每路记录实际相机速度；位置/旋转/速度取自真实运行状态。C/D 的受控人物标识与开始操作信息记录在各自第三人称路的数据中；不擅自改名或新增 JSON 键。systeminfo：gameProcessName / x,y / width,height / recordDpi。action_camera 逐帧：time（`YYYY-MM-DD HH:mm:ss.SSS`）、fps、frame、camera_position、camera_rotation_oula（[X,Y,Z] 度）、camera_rotation_quaternion（[x,y,z,w]）、camera_Follow Offset、camera_intrinsics（fx=fy，cx/cy 像素）、camera_speed；受控路加 player_position/rotation_oula/rotation_quaternion/speed；metric_scale；keyCode；mouse_x/y∈[0,1]；mouse_dx/dy∈[-1,1]。同一世界线内系统时间偏差 <100 ms。（本模块的键名与帧号按交付包判，即需方样例 demo4 #8 的写法：`camera_follow_offset`、`mouseX`/`mouseY`、frame 从 1 起；键鼠字段每一路都带——需方 2026-09-29：自由运镜按运镜路线换算、固定机位全程无按键、鼠标为 0。）

**验收**：完整性与同步、systeminfo 与真实值、真实输入一致、C/D 区分改变/未改变、共视/主体/运动像素三项分别验收、画质与音频、固定机位；抽检每场景 2 条 video+JSON 都挂退整包，另抽 5% video 通过率 <90% 退整包。

**需方 demo 跟进表（demo4 = 09-22 GTA5 demo 的 8 条反馈）**：未实现预计的运镜封装；镜头快速靠近角色疑似穿模；镜头方位长期固定在角色背面俯视角、视角变化不足；第四路相机离主体过远、占比太小；画面出现类百叶窗闪动；角色移动时边缘拖影/重影（抗锯齿）；FOV 不符合三期要求、主角占比过小；**键盘映射错误、鼠标映射错误、无 QE 映射**（反馈结果列附有需方 `action_camera.json` 样例附件）。历史 demo1–3 反馈：体积雾遮挡、素材锯齿、键鼠映射错误、滑步/抽搐/瞬移、穿模、投影丢失、FOV 畸形、边走边加载、闪线、主体出画过长。

## 判定方法要点与阈值

- 运动参数由位姿有限差分反算，不信任 `camera_speed`；四元数夹角用 atan2 形式（见 `engine_qc.mathutil`）。
- 相机本体系 R/U/F = 四元数旋转 (1,0,0)/(0,1,0)/(0,0,1)（docs/69 y-up 左手系）。六向平移：每向累计位移 ≥0.8 m（与 `engine_qc` 粉色平移诚实性同值）。
- 输入一致性：按键帧中本体系速度分量符号与键位方向一致率 ≥70%（滞后 0–6 帧搜索）；鼠标 dx/dy 与偏航/俯仰速率 Pearson |r| ≥0.4（滞后 0–10 帧）；人物路 WASD 按下帧中人物速度 >0.3 m/s 占比 ≥70%。
- 几何代理：点在视锥内 = 本体系 z>0.05 且像点落在画幅内（受控人物放宽 0.3 m 角半径）；第一人称路人物本身不入镜，只用舞台中心做代理并标 WARN。
- 像素面：|Δ|>12 计运动、>20 计跨遍变化；黑帧均值 <8、白帧 >247、单帧亮度突变 >40；跳剪 = 相邻帧变化 >90%；冻结 = 逐位相同 ≥15 帧。
- 交互键语义：键码 → 中文关键词表（`checks_worldline.KEY_SEMANTICS`），因果记录任一命中即视为已说明。

## 待需方确认、不能写成硬 FAIL 的口径（报告里为 WARN）

运动像素 ≥50% 的判定方法/时间口径/相机运动是否计入；共视的参与相机范围与多人主体判定；第一人称路的「动态主体」；追背 FOV 30–55 按水平还是垂直；游戏镜头（追背/第一人称）是否套 p95 上限；一组 12 路是否统一画幅；各游戏 FOV 取值；B 无跟随目标时 Follow Offset 的填法；C 接管窗口是否随 120 s 扩展；开头静止段是否可交付；接管时刻/受控人物标识进数据的字段定义（不得擅自新增键）。

## beach-demo-001 实测（2026-09-24，内部演示件）

组判定 FAIL：586 条规则，PASS 453 / FAIL 20 / WARN 55 / MANUAL 41 / SKIP 17 / UNVERIFIED 0，全量 43 s。
