# 四世界线：场景与剧本编写指南

给要**新写一个场景**（换地点、换人物、换剧情）的人。怎么操作录制、导出、出包在
[RUNBOOK-MC4-FOUR-WORLDLINES.md](RUNBOOK-MC4-FOUR-WORLDLINES.md)；本文讲**写什么、怎么写才不返工**，
内容全部来自 beach-demo-001 → 003 三组交付里需方的反馈和我们踩过的坑。

完整样例：[examples/stage-beach-demo.txt](examples/stage-beach-demo.txt)（剧本，注释里写了每个决定的原因）、
[examples/stage-group.beach-demo.json](examples/stage-group.beach-demo.json)（组配置）、
[examples/stage-calibration.beach-demo.txt](examples/stage-calibration.beach-demo.txt)（预演量出的标定）。
新场景照着这三个文件改。

## 一、一个场景由什么组成

| 文件 | 写什么 | 谁读 |
|---|---|---|
| 剧本 `stage-*.txt`（`dm-gta-stage-spec/1`） | 舞台在世界里的位置、人物、动作、路径、道具、陈设、因果规则、三遍各由什么程序操控 | 控制器（原生）与出片程序 |
| 组配置 `stage-group.*.json` | 时长、游戏时间与天气、B 自由相机起点、C 接管谁 / 第几秒 / 走哪条路线、D 的第 7 人、组自带的标定 | `stage-group-prepare` |
| 标定 `stage-calibration.*.txt` | 每个动作量出来的时长、脚离地高度、步速；座位量到的位置 | 控制器 |

剧本文本的哈希进每一遍的记录：**改了剧本就是另一组**（AB、C、D 都要重录）；只改 C 的路线（在组配置里）只重录 C；
只改出片算法（第一人称、追背的轨迹）只重出轨迹、单路重导；只改出包字段只重新出包。见第八节。

## 二、剧本语言

坐标是**舞台坐标**，单位米：`frame` 一行把舞台原点和朝向钉在世界里，之后 x 向右、y 向舞台深处（相机都在 y 负方向那一侧看过来），
朝向角 0 = +y、90 = −x（GTA 的朝向定义）。一秒 30 拍。

| 指令 | 写法 | 说明 |
|---|---|---|
| `frame` | `frame <x> <y> <ground z> <heading>` | 舞台原点的世界坐标、地面高度、朝向 |
| `ticks` | `ticks <30..18000>` | 一遍多少拍（120 s = 3600） |
| `clip` | `clip <id> <dict> <clip> <loop\|once\|walk>` | 给游戏动作起名：循环、一次性、走路 |
| `transition` | `transition [<actor>] <snap\|blend> [blend-in 速度]` | 换动作用混合（自然，姿势有几拍的小差异）还是硬切（精确但跳） |
| `contact` | `contact <clip\|*> <frame\|const\|off>` | 脚怎么踩地（2026-10-17）：`frame` 每一帧把最低的脚踝/脚趾放到模特自然站立的高度（站着的动作默认），`const` 整个动作取最低的那一帧（走、跑默认，跑步腾空时不往下拽），`off` 只用标定的整体高度（以前的做法）。见第四节 2 |
| `sink` / `lift` | `sink <0..0.1>`、`lift <clip> <−0.1..0.1>` | 全体下沉几厘米 / 单个动作抬高或降低几厘米。有了 `contact` 以后都不用了（沙滩演示两行都去掉了），只留作个别动作的手动微调 |
| `legik` | `legik <0..3> [IK 标志]` | 试过的：给演员开游戏自己的腿部 IK。实测对同步场景动画**完全无效**，别指望它 |
| `path` + `line` / `arc` | `path <id> <loop 0\|1> <x0> <y0> <heading>`，然后 `line <path> <m>`、`arc <path> <半径> <度>` | 走路路线，由直线和圆弧接成 |
| `actor` | `actor <id> <model>` | 一个人物 |
| `look` | `look <actor> <部件 0..11> <drawable> <texture>` | 换衣服鞋子（预演里用 `ped_look` 命令看效果） |
| `prop` / `propshow` | `prop <actor> <model> <bone>`；`propshow <actor> <clip> <from 0..1> <to 0..1>` | 手里的道具；只在某个动作的一段里显示它 |
| `beat` | `idle <loop clip> <秒> [at x y heading]` / `walk <walk clip> <path>` / `once <once clip> [at …]` / `pair <pair> <a\|b>` | 人物的时间表，按顺序一拍接一拍 |
| `repeat` | `repeat <actor> <第几拍>` | 从那一拍起循环到结束 |
| `pair` | `pair <id> <clip_a> <clip_b> <x> <y> <heading>` | 两人配合的同步动作 |
| `set` / `seat` | `set <id> <model\|备选…> <x> <y> <heading>`；`seat <actor> <set> <loop clip>` | 陈设；坐在某件陈设上 |
| `track` / `clear` | `track <id> <model 或 0x哈希> <x> <y> [半径]`；`clear <model 或 0x哈希 或 boats> <x> <y> <半径 1–300 m>` | 地图自带、会动的东西：逐帧记录；或开录前删掉、整遍不让它回来（`boats`：范围内所有船和摩托艇） |
| `rule` | `rule <id> <near\|touch\|aim\|damage> <actor> [m] then <actor>:<action>[,…] say <中文>` | 因果规则：玩家靠近 / 碰到 / 瞄准 / 打了谁，谁做什么反应；`say` 进交付说明 |
| `robot` | `robot <AB\|C\|D> <fly\|changed\|unchanged> <seed>` | 三遍各由哪个程序操控：B 飞自由相机、C 被接管的人、D 第 7 人 |
| `stance` | `stance game\|calm\|clip <dict> <clip>` | 被操控的人站着、没按键时怎么站（见下「第一人称」）；沙滩用 `clip mini@strip_club@idles@bouncer@base base` |

写错了 `stage-spec-check` 和控制器都会报到行，报错文字就是上表的写法。

## 三、动笔前先对齐的需求口径

详见 RUNBOOK 第四节和质检的条款目录（`../qc/worldline_qc/requirements.py`，R01–R50，报告里逐条列判定）。最影响剧本的几条：

- 一组 = A（3 路）+ B（1 路）+ C（4 路）+ D（4 路）= 12 路，每路 120 秒、30 帧/秒、1920×1080。
- A 是照剧本演的基线；B 与 A 同一遍，只是多飞一台自由相机；C 在第 N 整秒（N ∈ [0, 55]）接管 6 人之一，之后由键鼠操控到 120 秒，
  被打扰的人要有反应；D 多一个第 7 人在场上走，不打扰任何人。
- **每一路有人的时间 ≥ 80%**（96 秒），固定机位和第一人称也算。
- 固定机位一整遍不动，A/C/D 三处不同。焦距：固定 24，C、D 的追背 35、第一人称 35、自由运镜 50；A 的两条自由运镜 35 和 50，B 的自由相机 18。
  第一人称 10-16 起从 18 mm 改为 35 mm（需方嫌 18 广角感太强；10-16 会议给的 35–50，用户 10-16 定按毫米理解，所以不能用 24），
  C、D 每遍不再是四档各一次，需求的「四档各 25%」按整批算（质检 `quota.focal` 单组只报分布）。**35 mm 只有离人 3 米左右、正对着人
  才拍得到半个人以上**：路线要站得离人远些、正对着人（`tools/route_sim` 默认按 35 mm 算，`FP_MM=18` 复现旧组）。
- 追背和第一人称从第 0 秒就跟着待接管的人，接管时不切视角；画面不许急停、甩动；相机平移速度 p95 ≤ 6 m/s。
- 真实输入路（B、C/D 的追背）的键鼠是真实记录，第一人称的键鼠按头部相机的真实变化换算（需方 10-16：两路可以不一样）；
  C 接管前不带键鼠字段；自由运镜的键鼠由路线换算。
- 交付说明 v1.1（10-16）起每路多一个 `multicam_sync_i.json`（一组 48 个文件）：这一遍每拍每个动的东西在哪、朝哪、演什么动作，
  由录制日志生成（`gta_capture/stage_multicam.py`）。剧本里每个人的 id 就是交付里的 id，第 7 人是 `seventh`，手里的道具是 `人:模型`。
- 每帧的 `lighting`（太阳方向和强度，交付说明要求有主光源就填）来自组配置的 `environment.sun`：游戏没有读太阳方向的接口，
  是从导出画面里站着不动的人「头顶 → 影子尖」量出来的（`tools/sun_from_shadows.py`，样本在 `examples/sun-samples.beach-demo-113.json`）。
  录制时钟固定、暂停，整遍太阳不动，所以每帧同一个值；`intensity` 是项目统一的相对强度 1.0。这个值只对量它的地点、时间、天气有效
  （沙滩、12:00、EXTRASUNNY：太阳高度 56.3°、方位南偏东 17°，109 和 113 的影子逐像素重合），换地点（300 m 以外）、时间或天气，
  出包会直接报错，要用新组的画面重量（导一路固定机位就够：挑 8–10 个站着不动的人，读头顶和影子尖的像素）。

## 四、设计规则：踩过的坑

### 1. 不穿模

- **人与人**：站位按骨骼算距离，不按脚下的点。聊天的两人 0.93 m 面对面可以；`stage-spec-check` 会把任意两人骨骼最近的距离算出来。
- **脚与脚**：骨骼点在脚踝，脚掌还往前伸 20 多厘米，所以两人脚踝 < 0.40 m 画面里就是一只脚压着另一只——`stage-spec-check`
  的 clearance 单独判脚踝（`stage_check.FOOT_CLEARANCE_M`），手、头的 0.15 m 管不住脚。104 的游客走到东边拍照点时右脚踝离
  坐着的人左脚踝只有 17 cm，用户在第 2 路第 6 秒看出穿模（2026-10-17）；坐着的人原地转到朝 300° 后脚踝 0.79 m、任意骨骼 0.65 m。
  坐着、躺着的人腿伸得远，摆在别人的停留点旁边时先看朝向。
- **C 的路线离人**：离聊天男 ≥ 0.8、聊天女 ≥ 0.9、游客 ≥ 0.72、坐着的人 ≥ 1.2、慢跑者 ≥ 1.5 m（`tools/route_sim` 判）。
  想触发「靠近」规则又不碰到人，规则距离（1.2 / 1.0 m）要和这些数一起定。
- **相机与人**：追背相机在人身后约 4.4 m，由出片程序算（10-09 起）：有东西挡在中间就拉近到东西前面，旁人只在相机快碰到他时
  才让开、离他至少 0.4 m，所以路线从别人身边擦过时相机也会擦过；自由运镜的相机离任何人 ≥ 2 m、在各自的活动范围里（`stage_camera_paths.ROOMS`）；固定机位放在场外。
- **相机与东西**：剧本 `set` 摆的陈设自动当自由运镜的障碍物；**地图自带的东西**（旗子、救生塔、灯柱、树）程序看不见，新场景开录前
  要查舞台 16 m 内有什么，登记进 `stage_camera_paths.MAP_OBSTACLES`（世界坐标 x、y，半径，顶高）。定位：在两三个机位的交付
  画面（固定机位最好）上点同一个点，`python tools/locate_obstacle.py <剧本> <json>:<行>:<像素x>,<像素y> ...`，射线互相差几厘米就对了。
- **第一人称**：10-16 起朝身体的方向看、跟身体同时转，不滞后（需方：GTA 里头基本和身体一致，「开始转身的时候得对上不能有延迟」）；
  只动鼠标时第三人称镜头绕着人转、第一人称不动（需方同意）。眼睛在头骨外 20 cm、顺着视线，拍不到自己的头（001 的围巾穿模是眼睛在
  头里、视线朝后）。走路的上下颠簸按 5 拍平滑掉。上下方向固定平视（10-18 起，用户定）：录制程序为了第三人称的手感会让鼠标
  上下慢晃（低头 12° 上下各 3°、17 秒一个来回），第一人称以前跟着这个俯仰，站着不动也在点头。
- **第一人称站着不能晃**（需方：不接受无输入导致的第一人称画面变化，会上说「站着不要晃」）：第一人称跟着头走，所以要让人自己站稳。
  GTA 主角自带的站立动作会左右换重心，头每 1.6 秒左右摆约 21 cm（113 实测；10-17 只给眼位做了半秒平滑，验证时只量了一段
  7 秒的漂移就以为修好，其实画面还在左右平移 5–8 cm）。10-18 起剧本写 `stance`：人站稳 10 帧后淡入一段安静的站立循环，按键即淡出。
  试过 7 种（站稳后头在 2 秒内的摆幅）：默认 21.7 cm、关掉随机小动作（calm）21.7、保安 5.2、警察 8.4、街边 9.4/11.9、不耐烦 23.7、
  抱臂 7.6、**夜店保镖 0.5**（双手在身前交握，用户看过视频认可）。出轨迹时 `stage_tape` 会量被操控的那段（C 从接管起）站稳 1.5 秒后、
  起步 1.5 秒前头的摆幅，超过 1 cm 直接报错。换场景换人物要重测：同一个站立动作套在不同模型上摆幅可能不同。
- **道具**：只在用到的动作段里显示（`propshow`）。一直挂着的手机，收起来后会贴在背上、走路时穿在手掌里。
- **进出动作用游戏自己的**（如 `phone_in` / `phone_out`），不要拼；一个动作是给谁做的很重要：给男性做的拍照动作让女游客的鞋悬空，
  给游客配的收相机动作把相机塞进她没有的包里（003 把它去掉了，改成拿在手里）。

### 2. 脚要踩实

- **地要平**（用户 10-17：「沙滩高低不平」）：演员的动作是整段播放的，两只脚只有一个高度，地面一起伏就一只陷一只浮。
  选址先用控制器的 `ground_scan` 扫一遍地面高度（每 0.5–1 m 一个点），看演员活动范围里「25 cm 步距的高度差」——
  沙滩演示原址最大约 3 cm、整体 13 cm 起伏；码头以南 65 m 的新址 ≤ 0.4 cm。还要躲开游戏自己摆的沙滩道具（伞、毛巾、球：
  北边那片平台每 6–10 m 一组），用录制时写下的 `map-scan-begin.jsonl` 查。
- **脚的高度按帧算**（10-17 起）：标定时每个动作的每一帧都量最低的脚踝和脚趾，和同一个模特（同样的鞋）自然站在沙上时比，
  差多少就抬/降多少（`contact`）。站着的人不再整体下沉；以前的 `sink 0.02` 让聊天男人、游客、慢跑者陷进沙里 1–2 cm。
  预演的回包 `toes_over_ground_m` 逐拍给出每人脚趾离地多高，用 `tools/stage_rehearse.py` 汇总（排练别超过约 45 秒，回包太大会断管道）。
- 改动高度前先查剧本里旧的 `lift`：它们是配合旧 sink 定的（聊天女人那 2 cm 去掉 sink 后让她浮了 2 cm，103 因此作废重录）。
- 动作本身的脚位不对（叉腿的、单脚承重的）调高度救不回来，换动作或换模特更有效：003 的聊天女人换过一次动作。
- 躺平的人、躺椅在移动镜头下影子会闪（需方 09-27、09-28 两次反馈），用坐姿代替。

### 3. 动作自然

- 换动作用 `blend`，位置精确、姿势有几拍的小差异（需方接受）；`snap` 精确但会跳。
- 被打扰的人（规则反应 `watch`）看玩家 5 秒后走回原位、转回原朝向、从停下那一拍接着演，剧本不用管这段。
- 程序操控的人：在游戏的第三人称里演（游戏的第一人称会藏掉人的头），像正常玩游戏：镜头跟鼠标走，可以绕到侧面、正面；
  W、A、S、D 都用（GTA 第三人称里 A、D、S 是让人转向左、右、后方再走，不是横着走）。10-16 起（组配置 `"turn": "walk 40"`）
  程序不再替人转身，身体只由按键转：站着点一下键转 ≤ 45°（游戏自己转），大转身边走边拐。路线只走直线、停在空地、从人旁擦过，
  因为游戏里人的走法是死的：按下键后头 1.1 秒只朝按键那一刻的方向直走，松开后滑 0.5–1.5 m，转弯半径 1.6 m。
- **只在走路中转向，谁都不原地转身**（2026-10-17，用户看 105/107 的视频：打电话的人、游客拐弯脚打滑，背包的人点按转身也打滑）：
  - 剧本里的人：`arc` 半径 ≥ 1.2 m。走路动作是直着走的，套在 0.4 m 的小圈上身体每秒转 257°，脚就在地上蹭；1.2 m 约每秒 85°
    （跑步的人 4 m 大圈每秒 52°）。来回踱步改成全是左转的绕圈，停点放在直道上、面朝直道方向，每段路最后留 0.6 m 直道；
    动作的起停会让规划器多走或少走最多 0.87 m（让脚收拢），一圈圈累积会漂（打电话的人每圈往西漂 0.4 m），要调直道长度让每圈回到原地。
  - 程序操控的人：组配置 `"turn": "walk 60 straight"`。起步时只要目标方向和身体朝向差 ≤ 45°，就顺着身体朝向直着起步，走起来
    再用鼠标拐（最快每秒 60°，加上起步那 1.45 m 直走和身体跟镜头的延迟，实际转弯半径约 2.3 m），路线里不写 `tap`。
    所以每个停点前方要有约 3 m 空地（起步直走 1.45 m + 松键滑 0.5–1.5 m），停下时面朝哪边要靠来的路线方向定。
    模拟器加 `START_MAX=12 TAPS_MAX=0`：起步时身体偏 12° 以上、或有点按，这一遍算不合格（`tools/route_sim/README.md`）。
  - 左转绕圈用镜头在人右边（A）或身后（W）的键；镜头在左边的键（D、W+D）在模拟里跟不上圈，停偏 2 m、绕了 21 秒。
  - 舞台中间放不下 C 绕圈（剩约 3.7 × 3.3 m）。108 起 C 接管后往西走、从游客身旁 0.9 m 过（触发挡游客）、边走边往南拐出跑道，
    掉头回来停在舞台前 9.4 m，绕一个小圈回到同一处再停，然后每段 1.8 m 直着往北走、停在 7.6 m 和 5.8 m（第一人称 85.8%）；
    用户 10-17 晚嫌原来那版走得太远（最远 15.6 m、停在 5.6–12.8 m）。聊天的两人为此往西挪了 1.2 m。C 的自由运镜因此和 D 一样
    以舞台附近的点为锚（`stage_camera_paths` 的 `d2_player_anchor`），固定机位要按实录重搜（要拍全他 ≥ 98%）。
- **C 的干预要看得见**：至少一条「靠近」规则要触发（003：走到聊天两人身边 1 米站 3 秒，两人看他；游客从他身后擦过停下看他），
  不想要的规则（挡慢跑者）不能触发。需方问过「能不能更明显，比如推人一下」——程序目前只发 WASD 和鼠标，
  打人会引出通缉、两人逃走后第一人称就没人可看，所以还没做。
- **C 的第一人称要看得到人**：第一人称朝身体的方向看，所以少走多站、每站点键转身看着人（要 ≥ 80%）。
  后半段不要长时间站着（用户要求）。路线每步写按什么键（`w a s d wa wd sa sd`，`-` 让程序挑最近的）、`tap` 原地点一下转身、
  `step` 迈一步。按键时间表 `w:2,wd:1,sd:1,s:1`（鼠标不动、按表换键）只用来实测，正式路线不用（下一条）。
- **原地掉头**：游戏的原地转身 0.5–1 秒就转完，掉头时第一人称每秒转 90° 以上，需方 10-10 明确不接受；10-13 试过程序慢转
  （`glide`），但第一人称跟着慢转就落后于身体，需方 10-16 又要求不能滞后。**10-16 用户定：站着每下 ≤ 45°，大转身边走边拐，
  按键连着换走一段弧线**（需方的例子：W → W+D → S+D → S）。win-pc 当晚实测（arc-test-1016b）：走路中途每换一次键，身体半秒多
  猛转 45–110°（每秒 120–200°），第一人称最快每秒 189°、角加速度 p95 261、jerk p95 1968，全超需方上限（90 / 150 / 600）。
  **用户定方案 A**：大转身「按住一个键 + 鼠标慢慢转镜头」走弧线（转弯半径约 2.5 m），走路途中不换键；A/S/D 用在起步——镜头在人
  侧面或前面时按和身体同向的键，身体不用猛转。另：人一走起来，游戏镜头会自己往人背后转（每秒 15–30°，站着不转），程序用鼠标
  顶住。新路线在模拟器里按同一个 `TURN` 跑（`tools/route_sim/README.md`），第一人称超需方转动上限的一遍算不合格、看到人 ≥ 80%。
- **35 mm、第一人称跟着身体时，把人集中在舞台一侧**（2026-10-16）：人在游戏里永远面朝走的方向，C 往哪走、点按转身扫过
  哪边，第一人称就看哪边。人围在四周时，C 每次往回走都对着空沙滩（第一人称 67–79%）；003 改成人都在北半边、C 在南半边面朝
  他们以后到 82–90%。站点离要看的人 2–3 m 以上，每段路 ≥ 1.8 m；朝人点按每下会把人带近 0.3 m。
  35 mm 下 3 m 以内的人「半个人」进不了画面（坐着的人 1.5–2 m 处基本不算数），第一人称主要靠 2.5–3.5 m 外的人撑。
- **点按只用单键，转不够就多点几下**（2026-10-17，beach-demo-102 实录）：两个键（W+D、S+A……）的点按 41 下里 16 下
  直接走了 1 米，单键 27 下全是原地转身 —— 控制器现在只用单键点按（先用鼠标把镜头摆好再按）。一下最多转 45°，走到站点时
  身体差得多（102 的 D 走 1 冲过头 1 米，到站差 93°）就再点，最多 3 下；以前只点一下，D 对着空沙滩站了 14 秒。
- **新场景尽量少原地掉头**：给受控人物留出能绕着走的空地（转弯半径 1.6 m）。003 舞台中间只有约 2.3 × 3 米，2026-10-08 在
  模拟器里试过 3 种三角形、3 种长方形的绕法，第一人称有人的时间都只有 51–74%（要 ≥ 80%）、还会走不到停点，所以 003 只能来回走。
- D 的第 7 人在跑道外、舞台正前方的空地走走停停，离所有人 ≥ 1.8 m；每站转身面朝人群，走路的时间约占六分之一。
  10-16 起 D 也写路线（组配置 `seventh.route`，写法同 C），D 不触发任何事件（用户 10-16 定：C 有事件、D 无事件）。

### 4. 画面

- **背景不能空**（需方 09-27）：救生塔、沙滩车、伞、毛巾、包、冷藏箱这类陈设放在舞台后方 8–14 m，避开所有人的路线、
  水线的旗子；模型用 `a|b|c` 写备选，游戏里缺哪个自动换下一个。自由运镜绕着人群拍，陈设离人物常站处留 5 m 左右。
- **不糊**：游戏「后期特效」必须「高」或更低，「非常高 / 极高」会加景深，而导出用的是录制那台相机的对焦，近处的人是糊的
  （需方 09-29）。挂导出前程序会读设置文件，高于「高」拒绝挂；游戏里那个景深开关关了没用。
- **不拖影**：运动模糊 0。
- 天气 `EXTRASUNNY`、12:00；天上的飞机自动禁止生成、冒出来当帧删除，不用管。
- 录制锁 30 帧，交付的 fps 应全程 30；掉了帧先看 take 结果的 `frame_cap.late_frames` 和 `evidence/frame-timing.csv`（每帧的时间去向），别猜（RUNBOOK §四有 003 的例子）。

### 5. 相机

- 四路各自的职责、焦距和活动范围都在出片程序里（`stage_tape.py` 的 `LANE_ROLES`、`FIXED`、`stage_camera_paths.ROOMS`）；
  新场景通常只需要挪固定机位的三个点、调自由运镜的活动范围、登记地图自带的障碍物（`MAP_OBSTACLES`）。
- 自由运镜（RUNBOOK §四有全部数值）：每段都在动、速度看得出来，主要是环绕，夹着直上直下、直推直拉；每段至少一种六向平移以外的运镜；
  四路都看人群中点（C、D 的 10-09 起也是，需方：自由相机以观察事件为主）。交付说明会逐段列出实际的运镜和各类次数。
- 固定机位像人摆的三脚架（需方 10-13、10-16 会议）：高 ≤ 1.6 m、往下看 ≤ 10°，同时完整拍到 ≥ 3 人的时间 ≥ 95%，三遍各不相同；
  低处人会互相挡，所以还要没人被挡住连续超过 2 秒（受控人物 1 秒）。自由运镜：A 的看人群中点，C 的看事件（受控人物和被他影响
  的人），D 的看第 7 人；追背 35 mm 跟游戏镜头、离旁人 ≥ 1 m；第一人称 35 mm 在头上（10-16 以前 18 mm）。
  固定机位每遍录完后用 `tools/fixed_camera_search.py` 按这一遍的实录找（需方 rev 637：机位能观测主体全部行为）：
  受控人物会走到哪只有录完才知道，按估计放的 D 机位在 003 里让第 7 人走近时腿出画 8 秒。
  10-17 起（用户定）不再要求受控人物 98% 都在画，按需求挑「第 3 大的整身人最大」的机位（工具默认 `--min-played 0 --rank size`，
  人从 7–14% 高变成 20–30%）；但需求还有一条「所有路（含固定机位）动态主体可见 ≥ 80%」，质检把 D 的主体当作第 7 人
  （`worldline_qc` 的 `geo.subject_visible`）——109 第一版 D 机位不拍第 7 人，这一路判 0% 不合格，所以 **D 要加 `--min-played 0.8`**。
  只按「人最大」排会挑到只拍聊天两人的近景（其他人全出画），所以排的是第 3 大的人，不是全体的中位数。
- 相机不许急停、甩动，速度 p95 ≤ 6 m/s；轨迹按上限的 90%（自由运镜 75%）生成。

### 6. 键鼠

- C、D 的程序按组配置里路线每一段写的键走（`takeover.route` / `seventh.route`，10-17 起只在走路中转向、不原地点按），
  B 的飞行相机用 W/A/S/D/Q/E；八方向、没有鼠标就走不出斜角——这也是需方对真实输入路的要求。
- **路线的键要覆盖 W/A/S/D，含 W+A、W+D 斜走，也要有单独按 S 后退**（需求 rev 1295「一/三人称输入解耦」加粗条：
  「采集需覆盖 W/A/S/D 四键（含 W+A、W+D 斜走组合），不得只用 W」；10-18 用户定从 113 之后的下一组起做）。113 的追背路
  只有 W、A、D、A+S（编号 7、11），第一人称路只有 W（编号 8、12：按头部镜头换算，人往哪走就是「前」）。设计时注意：
  斜走时身体朝向和镜头差 45°，第一人称跟身体走，画面会跟着偏；单按 S 在 GTA 第三人称里是人转身朝镜头走，身体一下转 180°，
  要按「只在走路中转向」的规矩放在空地上、用 route_sim 先模拟转身速度（≤ 90°/s）和第一人称看到人的比例。
- C 的追背和第一人称在接管前**没有**键鼠字段（需方 09-30），接管那一帧起每帧都有；D 从第 1 帧起有；自由运镜和固定机位全程有。
- 第一人称朝游戏镜头的方向看，键鼠和画面对得上（10-07 起）；追背 10-09 起是算出来的、转向限速，快速转身时比鼠标慢 1–2 秒；
  B 自由相机带惯性。质检规则
  `input.eight_directions`、`input.mouse_drives_view` 每次出包都算。
- **自由运镜的键鼠只记看得出来的动**（需方 09-30：编号 6 有按键但画面没动）：某方向速度到 0.3 m/s 才记按键、降到 0.2 以下松开，
  一帧转动不到 0.01° 的鼠标记 0。50 mm 下 0.2 m/s 以下的移动每帧不到半个像素，看上去就是静止。
- **自由运镜要真的在动**：运镜段里一段 2–3 m 的推拉、升降如果摊在 20 秒里（0.1–0.2 m/s），画面基本是静止的——003 编号 6 的
  前 23 秒推近、37–60 秒拉远、最后 20 秒下降都是这样，需方 10-07 还指出按 E 画面没升（0.4 m 摊在 8 秒里，又被高度上限截掉）。
  10-07 起的程序：环绕每秒 6–16°、推拉每秒 0.6–1.0 m、升降 1.4–2.3 m 且每秒 0.4–0.8 m，按键帧画面中位每帧挪 6 像素以上。

### 7. 可重复性

- 同一份剧本每次摆出来要一样：**组自带标定**（预演量出的那份写进组配置 `stage_calibration`），AB 不再现场量。
- 组配置里的 `seed` 决定 B 飞行和 D 漫步的随机；C 走固定路线不随机。
- 四条世界线除玩家干预与它引起的反应外，所有人物每一帧位置逐位一致——出包时逐帧比对，比不上会说明。
- **随浪漂的东西每遍都不一样**：海上的浮具、浮标、浮球绳、摩托艇跳台跟着海浪动，三遍录下来位置差 1.6–1.8 m（109 的
  `msync.cross_*` 就挂在这），程序没法让海浪每遍一样。10-18 起（用户定）用 `clear` 在开录前把它们从游戏里删掉、并把
  这些型号在 200 m 内隐藏到这一遍结束；码头下浮台上停的摩托艇和快艇是「车辆」不是物件，地图扫描里看不到，用 `clear boats`
  删（同时关掉那片的刷车点）。take 结果的 `cleared` 是删了几个（同一个游戏里第二遍起常是 0：上一遍删的还没回来），
  `cleared_left` 是结束时又冒出来几个（> 0 就判这一遍不合格）。
  **但删不掉所有的**：红浮标、码头下的浮台、摩托艇跳台这类「地图本身摆的」，录制时怎么处理都影响不了导出——111 录前删掉、
  112 录前挪到固定位置冻住，两次导出第 1 路里它们都还在、照样随浪晃（回放播放时游戏按地图重摆、自己模拟海浪）。
  所以它们录制时记下的位置也不是视频里的样子，不跟踪；交付说明写明「随浪起伏、未记录」（10-18 用户定：就这样交）。
  浮球绳和船删了回放里确实没有。分辨办法只有一个：录一遍、导第 1 路、隔几百帧取图看它还在不在、动不动。
  新场景挨着水：先录一遍看 `map-scan-begin/end.jsonl`，开头结尾位置或朝向变了的地图物体就是会动的，在水里的先试 `clear`
  再按上面的办法验；岸上要留在画面里的（旗子）写 `track`。

## 五、开录前必做（按顺序）

1. `python -m gta_capture stage-spec-check <剧本>`：语法、演员两两距离、固定机位拍不拍得全、自由运镜算不算得出。
2. C、D 的路线在模拟里跑 1000 遍（[tools/route_sim/README.md](tools/route_sim/README.md)）：C 只触发挡游客那条规则、离人距离、
   第一人称 ≥ 80%（模拟和出片用同一个视线规则：003 的 C 10-09 重录，模拟全程最低 83.9%、实际 83.9%）。**模拟里有的指标都要当成必须通过的条件**。
3. 预演（`stage_rehearse`）：看脚、道具、新人物的形象；定 `lift`；把量出的标定写进组配置。
4. 磁盘（每路约 10 GB）、游戏设置（后期特效「高」、1080p、30 帧锁）。
5. 录 AB，看 take 结果的 `log`（座位量到没有、陈设放上没有、飞机删除计数、慢帧数），再录 C、D。

## 六、录后必做

- C：`tools/route_sim/take_c_check.py`（离人、按键、站立、追背、第 1 路）和 `first_person_check.py`（第一人称 ≥ 80%），
  在导出之前跑；不合格就重录 C（RUNBOOK §二 第 3a 步）。003 现在的 C 路线 route_sim 里约六分之一不合格，这是预料之中的。
  D 也跑 `first_person_check.py`。
- 出四路轨迹 → 导出 → 收取（`pointer_frames` 必须为 0）→ 转视频 → 出包。
- 整包质检（RUNBOOK 第六节），和上一版逐条比；改了几路，变化就只该在那几路。
- **抽帧看画面**：接管那一刻、每次原地掉头、离人最近的几处、道具收放的地方。程序能算距离和角度，看不出「不自然」。

## 七、目前的已知限制

- 第一人称：10-16 起跟身体走、不滞后（`turn: walk 40`），站着每下 ≤ 45°，大转身按住一个键用鼠标拐；平滑 6 拍（前后对称、
  和身体最多差约 5°）才压得住走路时朝向的细抖（jerk）。
  `glide`（程序慢转，10-13）和 `steps` 仍可选，但第一人称会落后于身体或角加速度超标，需方 10-16 不接受滞后。
- 追背：10-16 起由录制时的游戏镜头算（跟鼠标走，可在侧面、正面），离旁人 ≥ 1 m；长时间站着时镜头绕人慢转。
- 固定机位 C、D 的位置（`stage_tape.FIXED`）是 10-16 用模拟走位搜的临时值，录完要按实录再搜。
- B 自由相机带惯性，按键与当帧运动方向一致 66%–83%。
- 需方口径未定的项（像素运动占比的算法、游戏镜头是否套用运镜上限、fps 用整数还是浮点）在质检里是 WARN / MANUAL，
  不会因为跑通过就消失。
